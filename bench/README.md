# bench: evaluation inputs

Everything the evaluation in `paper/sections/08_evaluation.tex` reads, regenerated
from fixed seeds. Python only; the Java harness (JMH, baselines) is WP5b.

```bash
# R + dagitty are needed for the reference answers; one way to get everything:
mamba create -n causal4j-bench -c conda-forge python=3.11 r-base r-dagitty rpy2 pgmpy networkx numpy pytest
mamba activate causal4j-bench
pip install -e 'bench/py[r,test]'

causal4j-bench all        # fetch -> covid -> synth -> workloads -> stats -> reference
pytest bench/py
```

Every step is idempotent: a second `causal4j-bench all` leaves `git status` clean.

| Command | Produces | Used by |
|---|---|---|
| `fetch` (runs `datasets/fetch.sh`) | `datasets/bnlearn/<name>/{<name>.bif.gz, edges.csv, meta.json}` for the 11 bnlearn networks; `datasets/checksums.txt` (SHA-256, recorded on first download, verified after) | Table III, RQ1–RQ5 |
| `covid` | `datasets/covid/{edges.csv, meta.json}` from `dev/seed-dag.cypher` (25 nodes, 78 edges, latent ids in `meta.json`) | Table III, running example, RQ5 |
| `synth [--only n=N]` | `datasets/synthetic/<model>-n<N>-d<D>-s<S>/{edges.csv, meta.json}`: ER and BA, n ∈ {100, 316, 1000, 3162, 10000}, average degree ∈ {2, 4, 8}, seeds 0–4 (150 DAGs) | Table III summary row, RQ1/RQ4 scaling |
| `workloads [--only a,b]` | `workloads/<dataset>/{pairs.csv, triples.csv, meta.json}`: 200 `(t, y)` pairs with `y ∈ de(t)`; 50 `(x, y, z)` triples per \|z\| ∈ {0, 1, 3, 10} (capped at n − 2); seed 20261111 | RQ1–RQ4 query workloads, RQ5 |
| `stats` | `datasets/datasets.csv` and `paper/tables/datasets.tex` (Table III body) | Table III |
| `reference [--only a,b] [--no-dagitty] [--force]` | `reference/<dataset>/{dsep.json, adjustment.json, meta.json}`; an existing result is kept while its workload is unchanged (`workload_sha256` in `meta.json`), because timeouts make a recompute machine-dependent | RQ5 oracle; WP2 fixture (`reference/alarm/adjustment.json`, `reference/sachs/adjustment.json`) |

**Committed vs regenerated.** `edges.csv` and `.bif.gz` of bnlearn and synthetic
datasets are gitignored (regenerated byte-identically by `fetch` / `synth`); their
`meta.json`, the covid dataset, workloads, reference answers and `datasets.csv` are
committed.

**Formats.** `edges.csv`: header `from,to`, ids as strings. `triples.csv`: `x,y,z` with
`z` as `;`-separated ids (empty allowed). `adjustment.json`:
`{"dataset", "dag", "pairs": [{"t", "y", "canonical": [..] | null, "minimal": [[..], ..] | null, "minimal_count": int | null, "identifiable"}]}`;
`dsep.json`: `{"dataset", "dag", "triples": [{"x", "y", "z", "pgmpy", "dagitty"}]}`.
Sets are listed in the dataset's node order.

**Reference provenance** (per dataset in `reference/<dataset>/meta.json`):
d-separation from pgmpy (`DAG.is_dconnected`, negated) and dagitty (`dseparated`),
asserted equal; canonical set computed from the definition (Perković et al. 2018) and
validated with pgmpy in the proper backdoor graph, asserted equal to dagitty's
`adjustmentSets(type = "canonical")`; minimal sets from dagitty
`adjustmentSets(type = "minimal", effect = "total")`. Minimal families can be
exponential (one andes pair has 6404 sets) and R cannot interrupt dagitty's V8 engine,
so dagitty runs in a worker process killed after 30 s per pair (`minimal` and
`minimal_count` null); a family of more than 1000 sets is stored by size only
(`minimal` null, `minimal_count` = size). Both cases are counted in `meta.json`.
Latent nodes (covid only) are excluded from adjustment sets. Without R + dagitty,
`dagitty`, `minimal` and `minimal_count` are null.

**Caps.** Reference answers for synthetic graphs are computed only for n ≤ 1000
(dagitty's R implementation is slow beyond that), and minimal families only for
n ≤ 316; synthetic graphs with n = 1000 carry d-separation verdicts and canonical sets
only. bnlearn and covid get everything. The paper's RQ5 paragraph must state these caps
and the per-dataset timeout / too-many counts from `reference/<dataset>/meta.json`.
