# bench: evaluation inputs

Everything the evaluation section of the paper (janez87/Causal4j, `sections/08_evaluation.tex`) reads, regenerated
from fixed seeds. Python only; the Java harness (JMH, baselines) is WP5b.

```bash
# R + dagitty are needed for the reference answers; one way to get everything:
mamba create -n causal4j-bench -c conda-forge python=3.11 r-base r-dagitty rpy2 pgmpy networkx numpy pytest
mamba activate causal4j-bench
pip install -e 'bench/py[r,test]'

causal4j-bench all        # fetch -> covid -> synth -> workloads -> stats -> reference
pytest bench/py
```

Every step is idempotent: a second `causal4j-bench all` leaves `git status` clean.

| Command | Produces | Used by |

**Committed vs regenerated.** `edges.csv` and `.bif.gz` of bnlearn and synthetic
datasets are gitignored (regenerated byte-identically by `fetch` / `synth`); their
`meta.json`, the covid dataset, workloads, reference answers and `datasets.csv` are
committed.

**Formats.** `edges.csv`: header `from,to`, ids as strings. `triples.csv`: `x,y,z` with
`z` as `;`-separated ids (empty allowed). `adjustment.json`:
`{"dataset", "dag", "pairs": [{"t", "y", "canonical": [..] | null, "minimal": [[..], ..] | null, "minimal_count": int | null, "identifiable"}]}`;
`dsep.json`: `{"dataset", "dag", "triples": [{"x", "y", "z", "pgmpy", "dagitty"}]}`.
Sets are listed in the dataset's node order. Reference files hold one compact row per line;
synthetic ones are gzipped (32 MB of minimal families otherwise), written with `mtime = 0`
so they stay byte-identical across runs.

**Reference provenance** (per dataset in `reference/<dataset>/meta.json`):
d-separation from pgmpy (`DAG.is_dconnected`, negated) and dagitty (`dseparated`),
asserted equal; canonical set computed from the definition (Perković et al. 2018) and
validated with pgmpy in the proper backdoor graph, asserted equal to dagitty's
`adjustmentSets(type = "canonical")`; minimal sets from dagitty
`adjustmentSets(type = "minimal", effect = "total")`. Minimal families can be
exponential (one andes pair has 6404 sets) and R cannot interrupt dagitty's V8 engine,
so dagitty runs in a worker process killed after 30 s per pair (`minimal` and
`minimal_count` null); a family of more than 1000 sets is stored by size only
(`minimal` null, `minimal_count` = size). Both cases are counted in `meta.json`.
Latent nodes (covid only) are excluded from adjustment sets. Without R + dagitty,
`dagitty`, `minimal` and `minimal_count` are null.

**Caps.** Reference answers for synthetic graphs are computed only for n ≤ 1000
(dagitty's R implementation is slow beyond that), and minimal families only for
n ≤ 316; synthetic graphs with n = 1000 carry d-separation verdicts and canonical sets
only. bnlearn and covid get everything. The paper's RQ5 paragraph must state these caps
and the per-dataset timeout / too-many counts from `reference/<dataset>/meta.json`.

## Benchmark harness (WP5b)

The `bench` Maven module (JMH 1.37, embedded Neo4j 2025.05 with GDS 2.19) measures
Section VIII on the inputs above. Build once with
`mvn -B package -pl bench -am -DskipTests` (→ `bench/target/bench.jar`); the scripts
build it if it is missing. Python steps need the conda env above plus
`pip install -e 'bench/py[r,plots,external]'`.

```bash
bench/run_all.sh                      # everything, then results_to_tex; prints the run id
RUN_ID=<id> bench/run_all.sh          # resume an interrupted run (finished steps are skipped)
BASE_RUN=<id> bench/run_all.sh        # new run that reuses every output <id> already has; results_to_tex merges them
bench/run_quick.sh                    # CI subset, < 5 min
bench/export_paper.sh <run-id>        # copy tables/figures/numbers.tex into ../Causal4j-paper (never commits)
```

Each run writes `bench/results/<UTC>-<hash>/` (JMH JSON, CSVs, `environment.json`,
`timeouts.csv`, `wall_time.txt`) and `results_to_tex` writes `bench/out/<run-id>/`.
Results are never overwritten; both directories are gitignored.

`numbers.tex` defines every macro listed in the paper's `numbers-defaults.tex` (read from
`--paper-dir`, default `../Causal4j-paper`): the measured value, or that file's `\TODO`
default. Nothing under `bench/` writes outside `bench/out/<run-id>/` (and `bench/results/`);
`export_paper.sh` copies that directory into the paper checkout, then runs `latexmk` on
`main.tex` (landscape version), `full_version.tex` and `technical.tex` and prints the three page counts.

**Protocol.** Pure-Java benchmarks: `SampleTime`, 3 forks, 5 × 1 s warm-up, 10 × 1 s
measurement. Embedded-DBMS baselines: 1 fork, 3 + 5 iterations. Forks get `-Xmx4g`.
Medians and p99 come from the JMH sample histograms. Cypher and GDS queries run in a
transaction with a 60 s timeout; a timed-out query goes to `timeouts.csv`, and after
3 timeouts an operator is censored for the rest of its trial. Any (system, dataset,
operator) with a timeout is drawn as an open marker at 60 s and excluded from speedups.
The external round-trip stops a (library, operator) after 60 s of queries (`censored`).

**Wall time.** Run `20261002T201303Z-4fb92af` (Apple M3 Max, 16 cores, 128 GB, JDK 21,
forks at `-Xmx4g`): about **48 h** of measurement. RQ1 tier (a) + Cypher + GDS + RQ2:
23.6 h; RQ4 (150 graphs × 5 operators × 3 forks): 22.7 h; external round-trip: 1.6 h.
The run was resumed once after the round-trip hung inside DoWhy (now cut by a per-query
timeout), so its `wall_time.txt` covers only the resumed part. Do not use the machine
for other work during a run: timings are single-machine and noise-sensitive.
